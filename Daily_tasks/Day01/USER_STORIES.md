# Car Rental Management — User Stories

## User Stories

| ID | Functional Requirement | User Story | Story Points |
|---|---|---|---:|
| US1 | FR1 | As an Admin, I want to manage branches and vehicles so that I can maintain the rental fleet and branch information. | 5 |
| US2 | FR2 | As a Customer, I want to search for available cars for a selected period so that I can choose a suitable vehicle for rental. | 3 |
| US3 | FR3 | As a Customer, I want to book a car after uploading my driving licence details so that I can complete the rental booking. | 5 |
| US4 | FR4 | As a Staff member, I want to record vehicle pickup details including odometer reading and fuel level so that the vehicle condition at pickup is documented. | 3 |
| US5 | FR5 | As a Staff member, I want to record vehicle return details and inspection notes so that the vehicle condition after rental is documented. | 3 |
| US6 | FR6 | As a System, I want to calculate rental and additional charges so that the customer is charged the correct amount. | 5 |
| US7 | FR7 | As an Admin, I want to block vehicles for maintenance so that unavailable vehicles cannot be rented. | 3 |
| US8 | FR8 | As an Admin, I want to view vehicle utilisation percentage so that I can monitor how effectively the fleet is being used. | 3 |

## Definition of Done

A user story is considered Done when:

- The requirements are implemented according to the user story.
- Code is completed and follows project coding standards.
- Unit/integration tests are written and passed.
- The functionality is tested successfully.
- No critical or high-priority defects remain.
- Code is reviewed and committed to the repository.
- Documentation is updated where applicable.
- The functionality is ready for demonstration.
